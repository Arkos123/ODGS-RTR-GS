这是一个很好的问题，涉及到两个光栅化器的核心差异。让我分析一下。

## 根本原因：投影方式不同导致同一组高斯有不同的"视觉表现"

### 1. SGS 的 Equirect 光栅化器是"全包围"渲染

SGS rasterizer (`camera_type=3`) 的工作方式是：

- **深度排序依据**：径向距离（radial distance from camera center）——点到相机中心的直线距离
- **覆盖全部 360°**：没有近/远裁剪面，所有方向上的高斯都被渲染
- **ERP 畸变**：极地像素覆盖更少球面面积，同一个高斯在极地投影很小

### 2. 透视光栅化器是"锥形"渲染

RTR-GS 的透视 rasterizer 的工作方式是：

- **深度排序依据**：视图空间的 Z 坐标（`p_view.z`）——沿视线方向的深度
- **视锥体裁剪**：`p_view.z <= 0.2` 的高斯直接被过滤（`auxiliary.h:155`）
- **透视投影**：tan(FoV/2) 投影矩阵，近大远小

### 3. 差异的关键

想象 SGS equirect 训练产生的一组高斯。在它们中存在一些**径向拉长**的半透明高斯（floaters），位置在相机周围：

```
                    [floater]
                       |
                       |
  [场景物体] ←—————— 相机 ——————→ [场景物体]
                       |
                       |
                    [floater]
```

**在 equirect 渲染中：**
- 这些 floater 按径向距离排序，和场景物体一起正确混合
- 它们在 360° 图像中只贡献每个像素的一小部分（被稀释在大量像素中）
- L1 loss 上看起来像一层淡淡的雾，不容易引起足够的梯度去消除它们

**在透视渲染中：**
- 落在相机和场景之间的 floater 占据了视野的很大比例
- 透视的近大远小效应让它们显得更大
- 深度排序让它们渲染在场景物体前面 → 遮挡视线
- 半透明的特性在这个窄视野下非常明显

### 4. 这不是"特殊处理"

**Equirect rasterizer 没有对 floater 做特殊处理**，只是同样的 floater 在不同投影下的**视觉显著性不同**：

```
ERP 渲染（1 个 floater → 分散到几万个像素）：
  L1 损失 ≈ 0.01/像素 × 几万像素 = 几百
  每个像素只感觉"稍微有点雾"

透视渲染（同一个 floater → 集中到几千个像素）：
  L1 损失 ≈ 0.3/像素 × 几千像素 = 几百  
  每个像素感觉"有半透明东西挡住了"
```

损失数值差不多，但视觉感受完全不同。

### 5. 所以这正是我们这次改动的目的

本次移植的 SGS 风格 densification（`_equirect_prune_mask`、纬度感知阈值、post-pruning）就是为了在 equirect 训练阶段**直接清理这些 floater**，而不是等到透视渲染时才暴露出来。配合 depth-derived normal 等几何损失，从几何上抑制浮游高斯的生成。

### 小结

|               | Equirect 光栅化器              | 透视光栅化器                               |
| ------------- | ------------------------------ | ------------------------------------------ |
| 投影范围      | 360° 全包围                    | 锥形视场                                   |
| 深度排序      | 径向距离                       | 视图 Z 坐标                                |
| 近裁剪面      | 无                             | p_view.z > 0.2                             |
| Floaters 表现 | 被稀释到全图，像薄雾           | 集中在视野前部，遮挡明显                   |
| 清理机制      | 需要专门的保守修剪（本次改动） | 透视训练本身有 weights 修剪 + 屏幕大小修剪 |

不是 equirect 做了特殊处理，而是同一个 floater 在两个渲染器中的**可见性权重不同**，这是 SGS 和透视两种 rasterizer 各自的投影方式决定的。

# 潜在解决方案

SGS 本身训练时在 equirect 视角下看得干净，但换到透视就会暴露出浮游高斯——说明 **equirect 的训练信号对抑制 floater 不够强**。以下是几种可行的思路，按成本排序：

## 方案 1：SGS 训练后脚本清洗（最便宜）

写一个脚本，对 SGS 输出的 PLY 按几何启发式修剪 floater。Floaters 通常有可识别的特征：

| 特征           | 阈值（经验值）                       | 理由                             |
| -------------- | ------------------------------------ | -------------------------------- |
| 不透明度极低   | `opacity < 0.01`                     | 半透明的通常是未成熟的 floater   |
| 各向异性极高   | `max_scale / min_scale > 15`         | 细长高斯很可能是"触须"状 floater |
| 尺度远大于场景 | `max_scale > 0.2 * scene_extent`     | 漂在空中的巨大高斯               |
| 远离场景中心   | `position` 距离主点云超过 N 个标准差 | 孤立的浮游点                     |

可以做到每个步骤保留 95%+ 的有效高斯。脚本做成 `script/clean_sgs_ply.py`，在 `sgs2rtrgs.py` 转换前或作为其中的一个可选步骤运行。

## 方案 2：SGS 训练时启用更激进的修剪

SGS 的 `_direct_prune_mask` 默认非常保守（`prune_start_iter=7000`，`max_prune_ratio=0.03`，且 `screen_size_prune=False`）。在 SGS 训练时修改参数：

```bash
# 更早开始修剪 + 更高比例
--direct_prune_start_iter 3000
--direct_max_prune_ratio 0.08

# 开启基于屏幕大小的修剪（在 equirect 视角下大 = 透视视角下可能更大）
--direct_enable_screen_size_prune True
--max_screen_size 20

# 开启基于世界大小的修剪
--direct_enable_world_size_prune True
--direct_world_size_prune_ratio 0.15
```

代价是需要重新跑 SGS 训练（几个小时），不确定效果是否值这个时间。

## 方案 3：利用多视角深度一致性清洗

这是更精确但更复杂的方法：
- 用训练好的 SGS 模型渲染所有训练视角的深度图
- 对每个高斯，检查它在多少个视角中与深度表面接近
- 如果某个高斯在大多数视角中都远离深度表面 → 它是 floater → 修剪

这相当于一套 **不需要 ground truth 的几何验证**。

## 方案 4：透视一致性损失（训练时）

在 SGS 训练中，周期性从当前场景中心随机生成一个透视方向，用预览 rasterizer 渲染并加入一个一致性损失。这样透视方向也参与梯度计算。实现成本较高，但可能是最根本的解法。

## 我的推荐

**方案 1（后处理脚本）** 性价比最高。原因：
- 不需要重跑训练
- 可以和现有的 `sgs2rtrgs.py` 组合成一个脚本
- 效果可调，不会破坏 SGS 在 equirect 下的质量
- 即使后面做了方案 3/4，后处理也能作为兜底
